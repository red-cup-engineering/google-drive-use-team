# Google Drive Use Team

This child enterprise owns three exact software-use purposes: store one new
file in Google Drive, retrieve one exact file from Google Drive, or list one
bounded page of Google Drive file metadata. The purpose selects the operation;
a caller never supplies an executable, HTTP method, endpoint, headers,
environment, retry policy, or generic operation name.

The child is directly contractable through ActivityStreams solicitation and
single-use invocation. A customer-custodied credential enters only at the live
invocation boundary and must match the non-secret credential-grant identifier
bound into the request, offer, and capability. Credential bytes never enter a
request, response, refusal, event, datom, or resource receipt.

Only this child owns its interior. Every service outcome is a normalized RMN
effect whose witnesses are appended through the hired RWIL/RDF provider. The historical
`content/exchanges/` record and packet harness predate this membrane and remain
evidence only; they are not an advertised service face.

No live Google call is authorized by installation or by a dry-run. Live use
requires the exact customer offer, capability, credential grant, configured
credential, and effects. The provider makes no retry and returns either one
typed product or one typed refusal.
